## 一、背景、目标与范围

### 1.1 用户与问题

面向在本机使用 zsh 的开发者，集中查看和维护命令别名、常用环境变量，减少手工定位配置、处理引号和误改无关内容的成本。

原方案记录的本机文件为 `~/.alias`（88 行）与 `~/.zshrc`（107 行），且 `.zshrc` 已加载 `.alias`。这是编写原方案时的现场记录，不能作为实现时的结构和加载关系保证。

### 1.2 第一版范围

- 仅 Tauri 桌面模式、macOS、zsh；浏览器明确提示需要桌面应用，不触发原生调用。
- 固定管理当前用户的 `~/.alias` 与 `~/.zshrc`，展示绝对路径；不支持自定义配置路径。
- 别名：规定语法内普通 alias 的新增、修改、改名、移动分组与删除。
- 环境变量：托管区块内字面量字符串的增删改和改名；区块外定义只读展示。
- 写操作先预览再提交，提供备份恢复和本次变更的终端应用命令。
- 配置文件是有效配置的唯一来源；不新增数据库表，不把完整配置复制到 localStorage。

### 1.3 第一版不包含

- Bash、Fish、远程主机、系统级配置和跨设备同步。
- 自定义脚本、函数、全局 alias、后缀 alias 的结构化编辑。
- 环境变量表达式、PATH 列表、密钥注入和自动切换环境。
- 自动执行配置、后台 source、自动向终端发送按键或修改进程环境。
- 自动创建加载关系、重排初始化顺序或修改其他启动文件。

### 1.4 成功标准

- 规定范围内全部操作通过第八节验收。
- 未编辑区域原始字节保持一致；无变化提交不写文件、不创建备份。
- 版本冲突、语法错误或区块异常时目标内容不变。
- UI 区分“文件已保存”“命令已复制”“当前终端状态未知”。

## 二、生效边界与交互

### 2.1 文件与进程状态

应用保存文件，不能直接修改已打开终端的环境，也不能确认用户是否执行了复制的命令。在一个终端应用变更，不影响其他终端或已运行的应用。

zsh 启动文件可能位于 `$ZDOTDIR`；`.zshrc` 在交互式 Shell 中读取，登录 Shell 还可能在其后读取 `.zlogin`。第一版只管理固定路径，不承诺所有启动方式都读取它。首次进入展示范围和目标；若应用可见的 `ZDOTDIR` 指向其他目录，显示路径不匹配说明并禁止写入。应用进程环境不能证明用户终端的实际配置位置。

展示“发现直接加载语句 / 未发现直接加载语句 / 加载关系无法静态确认”。只检查规定形式的顶层 `source ~/.alias` 或 `. ~/.alias` 等字面量路径引用，不执行配置探测。未发现时由用户检查，不插入 source 语句。

### 2.2 按操作定义生效

| 操作 | 文件变化 | 已打开终端的应用方式 |
|---|---|---|
| 新增 / 修改别名 | 写入新定义 | 复制并执行本次 alias 定义 |
| 删除别名 | 删除目标定义 | 用户选择执行本次 unalias 清理；只 source 不会清除旧定义 |
| 别名改名 | 同一提交删除旧条目、写入新条目 | 本次命令包含旧名称清理和新名称定义 |
| 移动分组 | 仅改变文件组织 | 无运行时变更，不生成应用命令 |
| 新增 / 修改变量 | 写入字面量 export | 本次 export 影响当前 Shell 和随后启动的子进程 |
| 删除 / 改名变量 | 删除旧定义，改名同时新增定义 | unset 会清除当前会话值，预览明确列出清理名称 |
| 恢复备份 | 恢复选定文件 | 提示重新开启加载对应配置的 Shell，不宣称同步当前会话 |

新启动且加载对应文件的 Shell 将执行保存后的内容；其他文件仍可能重新定义同名项。

删除托管变量不删除外部同名定义。`unset` 不会恢复此前被覆盖的外部值，提示重新开启 Shell。别名在其他文件中的定义也不受本次删除影响。

### 2.3 保存与复制

- 默认动作“预览并保存”，成功显示“已保存到文件，当前终端需手动应用”。
- 提供“保存并复制应用命令”和结果中的“复制本次变更命令”。
- “保存后自动复制”偏好默认关闭；localStorage 只保存偏好，不保存命令正文。
- 命令由后端根据已提交变更生成，只包含经校验名称、安全转义的值和本次清理，不执行配置中的其他语句。
- 删除、改名的清理影响在预览中确认；不批量清空 alias 或变量。
- 保存与复制分别反馈。复制失败显示“文件已保存，命令复制失败”，不能提示保存失败。
- 不显示“所有终端已生效”。
- 顶栏“刷新文件视图”重新读取文件，不代表重载用户终端。
- 不默认生成 `source ~/.alias && source ~/.zshrc`：`.zshrc` 可能再次加载 alias，并重新执行初始化和 PATH 拼接。完整重载由用户在终端自行操作。

## 三、解析与编辑规则

### 3.1 通用规则

- 保留原始内容和位置范围，以字节区间生成补丁；提交使用完整候选文件原子替换。
- “按行编辑”表示语义修改范围，不表示非原子的原地覆盖。
- 支持 UTF-8、LF / CRLF，保留换行形式、空行和末尾换行状态；新建使用 UTF-8 / LF。
- 非 UTF-8、混合换行或超过 1 MiB 的文件说明原因并禁止结构化写入。
- 新行沿用文件格式；追加区块必要的分隔换行纳入差异。
- 读取、解析、预览不执行文件，不使用 eval 或通过执行 source 取得值；候选语法检查见第四节。
- 名称和值由后端再次校验，前端检查不能替代后端约束。

### 3.2 别名：有限语法编辑

可编辑范围为顶层、单行、单个普通 alias 定义，名称符合 `[A-Za-z_][A-Za-z0-9_-]*`，值可静态还原为命令文本。

```zsh
alias gs='git status'
alias gs="git status"
alias gs=git
alias ll='ls -l' # 行尾说明
```

- 支持单引号及表示单引号的标准引号拼接，明确词法规则并测试。
- 双引号值仅在不含参数展开、命令替换和算术展开时可编辑，按 zsh 规则处理转义。
- 无引号值仅支持不含展开或 Shell 运算符的单个词；含空格需引号或规定范围内转义。
- 写入统一安全单引号转义；命令文本中的 `$`、命令替换保留到用户调用 alias 时解释，不能在加载定义时提前展开。
- 多定义同一行、跨行、条件 / 函数内定义、`alias -g` / `alias -s`、动态值或混合其他命令保留原文，显示位置和不可编辑原因。
- 解析器必须确认顶层归属，不能用逐行正则把函数、条件或 heredoc 内文本识别为可编辑项。
- 前后空格保留；alias 尾部空格可能影响后续展开，不自动 trim。

操作规则：

- 新增和编辑分开；新增遇同名拒绝，不用 upsert 隐式覆盖。
- 已有重复名称逐条展示并提示，不新增重复名称。
- 修改和删除绑定原条目身份，不只传名称或行号。无法确认动态定义影响时说明检测范围，不声称知道最终定义。
- 改名在同一文件提交中移除旧项、写入新项；新名称冲突拒绝。
- 修改保留缩进与行尾注释；删除只移除定义行，保留独立注释和空行。

### 3.3 别名分组

- 新分组用独立注释 `# xlt-group: <名称>`；非空、最长 80 字符、不含换行。
- 原有独立注释段可作为候选，标注“原文件注释分组”；行尾注释不是标题。
- 分组用于展示和定位；同名标题以来源位置区分。
- 新增放在选定分组末尾、下一分组之前；无分组则追加末尾。
- 移动只移动目标定义行及行尾注释，不移动独立注释；空分组不自动删除。
- 创建分组、插入和移动均纳入预览。

### 3.4 环境变量：唯一托管区块

边界标记固定、独立成行，说明文字放在区块内：

```zsh
# >>> xlt-managed env >>>
# 由 xlt-workbench 管理；编辑前请在应用中刷新文件视图
export ZENTAO_URL='https://zentao.goktech.cn/zentao'
export HTTP_PROXY='http://127.0.0.1:8798'
# <<< xlt-managed env <<<
```

- 无标记时首次保存必须预览并确认顶层插入锚点，显示前后初始化语句，不能固定追加末尾；已有区块原位编辑。
- 已实现的英文说明起始标记作为明确旧格式识别，在预览中规范化；不能把旧区块当作缺失而重复创建。
- 标记必须在顶层，无法确认时禁止写入。
- 重复、缺失、倒置、嵌套标记或区块含不支持语句，显示具体问题并拒绝写入。
- 仅允许空行、独立注释和规范字面量 `export KEY='value'`；名称唯一。
- KEY 符合 `[A-Za-z_][A-Za-z0-9_]*`；第一版禁止托管 `PATH`、`HOME`、`ZDOTDIR`、`ENV`、`BASH_ENV`，说明其影响和范围限制。
- VALUE 为字面量字符串，可为空；不含 NUL、换行，最长 8192 个 UTF-8 字节，统一安全单引号转义。
- 输入 `$HOME/bin` 保存字面量 `$HOME/bin`；表单标注“不执行变量展开”。
- 区块内重复是结构错误；新增 / 改名遇托管同名拒绝。与区块外同名时展示来源和覆盖提示，预览确认后提交。
- 变量只从插入位置起设置，不能影响前面已执行的初始化；展示限制，不自动重排 Kiro、SDKMAN、mise 等工具区块。
- 区块前可能 return / exit，区块后也可能重新定义变量；语法通过不证明区块必定执行或值最终有效。
- 保留区块内未编辑注释；删除最后一项后保留空区块。

### 3.5 区块外静态定义视图

- 展示当前 `.zshrc` 可识别 export 的 KEY、原始表达式、来源行和静态上下文，全部只读。
- 条件、函数、多行或动态定义标记“动态 / 条件定义”，不计算运行时值。
- 注明“仅展示当前文件可识别的定义，不代表当前终端完整环境”；不递归加载其他配置。
- 同名检查只覆盖当前扫描文件；无法判断的定义纳入问题列表。
- “在文本编辑器中打开配置文件”由后端按固定目标和参数数组调用系统文本编辑方式，不接收任意路径或命令。

## 四、文件操作契约

### 4.1 目标与状态

- 每个文件独立返回存在、类型、可读、可写、版本、格式、解析问题与语法状态。
- 缺失文件可显式预览创建，权限 `0600`，父目录必须已存在。
- 第一版拒绝写入软链接、硬链接数大于 1、非普通文件或所有者不是当前用户的目标；说明原因，不替换链接。
- 保留原文件权限位。ACL / 扩展属性必须证明保留；实现不支持时拒绝写入并说明。
- 写入与打开仅接受 `aliases | zshrc` 枚举，后端解析固定路径；恢复只接受备份 ID。
- 临时文件、备份限制访问；日志和错误不打印完整配置、值或应用命令。

### 4.2 统一预览与提交

1. 读取内容 SHA-256、目标身份和元数据；缺失文件有明确版本状态。
2. 生成候选完整内容，返回差异、影响名称、问题、确认提示与候选摘要。
3. 用户确认当前计划；表单变化后旧预览失效。
4. 按文件串行提交，在同目录以 UUID 名称排他创建临时文件，权限 `0600`。
5. 参数数组调用固定 `/bin/zsh -f -n <临时文件>`，5 秒超时、输出最多 64 KiB；失败或超时不提交。
6. 再核对目标身份、权限和内容版本；变化则报冲突，用户刷新后重新预览。
7. 备份当前原文件；失败则不替换。新建记录原文件不存在，不制造空备份。
8. 保留元数据、同步临时文件，最后检查目标后同目录 rename，再同步目录。
9. 返回最新版本、备份 ID、应用命令和独立维护问题；前端分别更新视图与处理复制。

约束：

- 候选完整文件语法通过才替换。`zsh -n` 不验证命令存在、source 目标或运行结果；徽章只写“语法检查通过”。
- `-f` 禁止常规用户启动文件加载，但系统 `/etc/zshenv` 仍可能被读取；不主动执行候选配置。
- 内容摘要用于版本判断，mtime 仅辅助；不能只用 mtime 或行号。
- 每个计划只操作一个文件，不提供跨文件批量提交。
- 原文件整体语法错误时拒绝写入，展示位置并提供打开文件入口。
- rename 前失败目标不变；rename 后目录同步失败返回“文件已替换，持久化确认失败”，保留备份并重新读取核实，不能报告“未保存”。
- 无变化返回“无变更”，不写文件、不占备份、不生成应用命令。
- 应用内部按文件串行化，只能检测可观察的外部修改；最后检查与 rename 间仍有竞争窗口，不能承诺与不遵守同一锁协议的编辑器完全隔离或跨进程原子 CAS。

### 4.3 备份与恢复

- 路径 `~/.xlt/backups/shell-env/<文件类型>/<时间戳-UUID>/`，目录 `0700`，备份及清单 `0600`。
- 清单记录 ID、类型、原目标、时间、内容摘要、权限和原文件是否存在，不索引变量值。
- 每个文件保留最近 5 个成功提交对应的历史版本，提交完成后清理超额历史。
- 清理失败单独提示“保存成功，备份清理失败”。
- 恢复展示时间、目标与整文件差异，明确覆盖备份后对该文件的修改，用户确认。
- 校验清单、备份摘要、候选语法、当前版本，先备份当前内容，再复用提交流程。
- 恢复不能绕过目标、权限、并发检查；第一版不提供将“原文件不存在”恢复为删除文件的操作。
- 恢复只确认文件状态，不能自动清理旧会话定义。

## 五、规范化模型与模块

### 5.1 数据契约

| 类型 | 信息 |
|---|---|
| `ShellFileSnapshot` | fileKind、绝对路径、状态、版本、格式、问题、语法状态 |
| `AliasEntry` | 快照内 entryId、name、命令文本、groupId、来源范围、可编辑状态与原因 |
| `EnvEntry` | 快照内 entryId、key、字面量或原始表达式、managed、来源、上下文、可编辑状态 |
| `ShellChangeRequest` | fileKind、expectedVersion、明确操作、原 entryId、原名称、draft |
| `ShellChangePlan` | planId、原版本、候选摘要、差异、影响名称、确认提示、过期时间 |
| `ShellCommitResult` | 提交状态、最新快照、backupId、可选应用命令、独立维护问题 |
| `ShellBackup` | ID、类型、时间、摘要、原文件存在状态、可恢复状态 |

- entryId 绑定来源范围和原始内容，快照版本变化后不能再使用；行号只展示。
- 配置取自文件；UI 偏好可存 localStorage，计划短期保存在内存，不持久化秘密内容。
- 计划有效期 5 分钟、最多 16 个、单次消费；关闭 / 替换预览主动取消；创建、读取、提交时清理过期计划，不新增轮询。页面卸载清理自身计划，应用退出释放内存。
- 稳定错误 code + 脱敏 message，区分输入不合法、范围不支持、冲突、区块异常、语法错误、超时、备份失败、替换失败和替换后持久化确认失败。
- Rust / TypeScript 使用 camelCase；保存和复制状态分别表示。

### 5.2 Rust 后端

使用独立目录，避免单个大文件：

```text
src-tauri/src/shellenv/
  mod.rs         # 模块组织
  types.rs       # DTO、约束、错误
  parser.rs      # 词法、来源、静态定义与问题
  serializer.rs  # 转义、补丁、本次应用命令
  files.rs       # 固定目标、版本、元数据、备份、原子替换
  plan.rs        # 预览绑定、短期计划、按文件串行提交
  commands.rs    # Tauri 边界
```

统一命令表，共 8 个命令：

```text
shell_config_read(fileKind)                -> ShellFileSnapshot + entries
shell_change_preview(request)              -> ShellChangePlan
shell_change_commit(planId, confirmations) -> ShellCommitResult
shell_change_cancel(planId)                -> ()
shell_config_validate(fileKind, version)   -> SyntaxCheckResult
shell_config_backup_list(fileKind)         -> Vec<ShellBackup>
shell_config_restore_preview(backupId, expectedVersion) -> ShellChangePlan
shell_file_open(fileKind)                  -> ()
```

- 恢复复用 commit，不另设绕过预览的直接写入口。
- 耗时文件操作和校验放在阻塞线程池；不阻塞 IPC 主线程，不在启动时扫描用户配置。
- 参考现有 MCP 的预览、版本绑定与备份设计，但独立于 Skills/MCP 开关和状态。
- 第一版先形成领域内文件能力，有第二个实际使用者后再提取公共模块。
- main.rs 模块、状态和命令遵守现有 diagnostic 隔离。

### 5.3 前端

- `/shell-env`，工具箱“Shell 环境”，图标 `i-lucide-terminal`。
- `src/views/tools/ShellEnvPage.vue` 用 `WorkspacePage` 承载 `src/views/ShellEnvView.vue`。
- 别名 Tab：名称、命令、分组、来源行、可编辑状态；搜索、折叠；所有写操作经统一预览。

- 值以纯文本显示；用户标记的敏感项掩码展示、按次揭示，差异也遮罩。标记仅为界面偏好，磁盘仍是明文。
- 顶栏：刷新文件视图、按文件语法状态、备份和打开文件。
- 预览展示目标、差异、覆盖与会话影响；确认项绑定计划。载入失败与空列表分开。
- `shell-env-service.ts` / `types/shell.ts` 封装命令；复制复用 `clipboardService.writeText()`。
- 保留已实现的源码编辑与来源行定位；源码保存也必须使用版本绑定、差异预览和统一提交。源码有未保存修改时禁止对同文件进行表格写入或恢复，离开页面需处理脏状态。
- 不把值发送给 AI、网络或统计服务；应用命令可能包含明文值，复制前明确说明。

## 七、衍生方向与发布边界

定位为“本机开发环境配置管理”，沿用来源、版本、预览、提交与备份契约；每项扩展独立验收。

以下为方向概览，执行顺序已由 [开发环境管理后续规划](./PRD-开发环境管理后续规划.md) 更新为：R0 现有能力收口 → R1 来源与 PATH → R2 项目 `.env` → R3 配置集 → R4 环境验证与秘密引用。

| 阶段 | 能力 | 边界 |
|---|---|---|
| 第一版 | 别名、字面量变量、预览、恢复 | 完成本 PRD，不增加自动执行机制 |
| 第二阶段 | PATH 专项管理 | 排序、去重、目录检查；单独定义展开与幂等规则 |
| 第二阶段 | 配置诊断 | 静态加载关系、重复与解析问题；说明扫描范围 |
| 第三阶段 | 工作 / 个人 / 代理配置集 | 明确覆盖、禁用、会话清理，不承诺同步所有终端 |
| 第三阶段 | 项目环境 | 优先限定应用启动的子进程，不默认覆盖全局配置 |
| 后续 | 多 Shell、迁移、导入导出 | 独立适配契约，导入先预览，秘密明文导出需明确选择 |
| 后续 | 密钥库引用 | 独立定义生命周期；写入 Shell 后是明文 |

改为独立托管文件加 source 时需另行定义加载位置、迁移与退出管理流程；本版继续采用已确认的 `.zshrc` 托管区块。

## 八、验收与验证

### 8.1 解析与语义

- 支持形式完成全部操作；引号、反斜杠、`$`、尾部空格、行尾注释按契约保留。
- 函数、条件、heredoc、动态、多行、特殊 alias 不误识别成可编辑条目。
- 未编辑区域字节级比对，不能只验证写回后可解析。
- 空值、Unicode、空格、单引号、美元符号和命令替换文本按字面量保存；读取和校验不执行候选内容。
- 异常区块和非法内容拒绝写入；同名冲突与覆盖确认绑定当前预览。

### 8.2 文件与恢复

- 覆盖新建、无变化、LF / CRLF、末尾无换行、权限、链接及不支持元数据。
- 外部修改即使 mtime 未变化也可检测，旧条目 ID 和计划不能提交。
- 同文件提交串行化，临时名称唯一；旧版本计划冲突。
- 语法错误、超时、备份失败和 rename 失败不改目标；替换后同步异常有独立结果。
- 备份 ID 唯一、权限正确、每文件 5 个历史版本，清理问题独立反馈。
- 恢复有整文件差异；损坏备份、当前版本变化或候选错误拒绝恢复。
- 文件测试使用临时目录和测试目标注入，不写真实用户配置。

### 8.3 会话与界面

- 隔离 zsh 子进程验证新增、修改、删除、改名；验证删除后仅 source 不清理旧定义。
- 验证重复加载 PATH 拼接样本会重复路径，UI 不将完整重载作为默认应用方式。
- 变量字面量不执行替换；alias 命令文本到用户调用时才解释。
- 自动复制默认关闭；保存与复制状态分离，应用不执行生成命令。
- 浏览器不触发 IPC，诊断包不注册模块、状态与命令。
- 表单变化使旧预览失效；敏感值不进入日志、错误或持久化计划。
