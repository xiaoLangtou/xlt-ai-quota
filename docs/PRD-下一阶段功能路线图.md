# xlt-workbench 下一阶段功能路线图

## 1. Summary

下一阶段不再继续横向增加独立工具，而是先完成当前改造、恢复已实现但关闭的 Skills/MCP，再把用量看板升级为主动提醒用户采取行动的工作台。路线图分为四个阶段：发布收口、安全启用 Skills/MCP、用量行动中心、统一备份与迁移。

## 2. Contacts

| 角色 | 负责人 | 说明 |
| --- | --- | --- |
| 产品负责人 | 项目维护者 | 决定阶段目标、范围和验收结果 |
| 技术负责人 | 项目维护者 | 负责 Vue、Tauri、Rust 和本地数据设计 |
| 验收用户 | 日常使用多种 AI 编程工具的个人开发者 | 验证数据、性能和使用路径 |

## 3. Background

项目已经不是单一的 AI 用量看板。当前代码同时包含用量分析、订阅账单、Git 报告、剪贴板、代码片段、密钥库、Skills 管理和 MCP 管理。

当前状态有三个重要事实：

1. 用量页正在进行较大幅度的界面与成本分析改造，工作区有约 900 行新增、516 行删除的未提交变化。
2. Skills/MCP 已具备扫描、安装、编辑、计划预览、备份、回滚和目录管理等能力，但正式配置仍以 `skillsMcp: false` 关闭。
3. Skills/MCP 的计划表、全量扫描、目录传输和第三方探测存在资源生命周期与工作预算问题，当前改造正在处理其中一部分。

本次检查结果如下：

- `pnpm typecheck` 通过。
- Rust 17 项单元测试全部通过。
- 前端冒烟测试的大部分业务检查通过；最后的功能开关测试仍按旧的 `main.rs` 结构匹配，尚未覆盖新加入的计划清理任务。

因此，当前最重要的产品问题不是“缺少页面”，而是：用户还不能稳定地使用已经完成的大块能力；用量看板也仍以查看数据为主，缺少明确的下一步行动。

## 4. Objective

### 4.1 总目标

让用户在打开应用后的 10 秒内回答三个问题：

1. 哪个 AI 工具现在可用，哪个即将触及额度？
2. 哪个连接器、Skill 或 MCP 配置需要处理？
3. 当前配置与本地数据是否可恢复、可迁移？

### 4.2 Key Results

| KR | 衡量方式 |
| --- | --- |
| KR1：发布基线可信 | 类型检查、前端单元冒烟、Rust 测试全部通过；功能开关测试覆盖计划清理任务 |
| KR2：Skills/MCP 可安全启用 | 空闲 30 分钟不触发扫描或网络同步；连续 100 次打开和关闭计划后，计划表不超过 32 项，过期计划按约定清理 |
| KR3：用户能快速处理异常 | 每个同步失败都显示数据源、最后成功时间、错误原因和可执行操作；用户可只重试一个连接器 |
| KR4：额度提醒有用且安静 | 同一额度窗口跨越同一阈值只提醒一次；提醒展示当前值、阈值和重置时间 |
| KR5：本地数据可迁移 | 一次导出并恢复设置、用量、订阅账单、片段和工具元数据；恢复结果有逐项统计和校验 |

## 5. Market Segments

### 5.1 多工具个人开发者

同时使用 Codex、Claude Code、Kiro、Qoder、Gemini CLI、OpenCode 等工具，需要判断额度、成本和可用性，不希望逐个打开控制台。

### 5.2 AI 工具重度用户

Token 和订阅支出变化快，需要在额度接近上限、连接器失效或成本异常时及时知道原因。

### 5.3 本地优先用户

希望凭证、用量、Skill、MCP 配置和工作记录保留在本机，并能主动导出和迁移数据。

共同约束：产品面向单机个人工作流；第三方登录态继续由各自 CLI 管理；应用不代理 MCP 流量；不执行片段、剪贴板内容或远程说明中的命令。

## 6. Value Propositions

| 用户任务 | 当前问题 | 下一阶段价值 |
| --- | --- | --- |
| 判断哪个工具还能继续用 | 需要打开应用后逐张查看额度卡 | 托盘和行动中心直接指出即将触及额度的窗口 |
| 修复数据同步 | 只能看到整体同步结果 | 精确到连接器查看状态并单独重试 |
| 管理 Skills/MCP | 能力已实现但正式入口关闭 | 在明确资源边界下重新启用，并保留预览、备份和回滚 |
| 更换电脑或重装应用 | 数据分散在 Web Storage、SQLite 和配置文件 | 用一个本地备份任务完成导出、检查和恢复 |
| 理解近期用量变化 | 图表提供事实，但行动建议有限 | 用异常、趋势和重置时间生成简短的本地洞察 |

产品差异不在于支持更多页面，而在于把多种本机 AI 工具的状态、配置和数据治理放在同一个本地优先工作台中。

## 7. Solution

### 7.1 UX and User Flows

#### 流程 A：打开应用处理今日事项

```text
打开概览
  → 查看“需要处理”区域
  → 选择额度提醒、同步异常、Skill 问题或 MCP 问题
  → 进入对应详情
  → 完成操作
  → 返回概览，事项从列表中消失
```

#### 流程 B：单独修复一个连接器

```text
连接与设置
  → 选择异常连接器
  → 查看数据来源、最后成功时间和错误信息
  → 按页面提示完成本机登录或配置
  → 单独同步该连接器
  → 查看额度和 Token 两类结果
```

#### 流程 C：安装或修改 Skill/MCP

```text
浏览或扫描资源
  → 打开详情
  → 选择目标 Agent 和范围
  → 查看变更计划与风险
  → 确认写入
  → 查看逐目标结果和备份记录
```

#### 流程 D：迁移本地数据

```text
设置 → 数据管理
  → 选择导出范围
  → 设置备份密码
  → 生成加密备份
  → 在目标环境导入
  → 预览将新增、覆盖和跳过的项目
  → 确认恢复并查看校验结果
```

### 7.2 Key Features

#### P0：发布收口与性能基线

这是所有新功能的进入条件。

- 完成当前用量页、成本分析和组件重构。
- 更新功能开关测试，使其验证 Skills/MCP 关闭时不注册模块、命令和页面，同时允许受开关约束的计划清理任务存在。
- 为用量同步、剪贴板监听、Skills/MCP 扫描和第三方探测记录耗时、结果数量和错误类型；日志不记录密钥、环境变量值或请求头值。
- 建立三类固定检查：冷启动、空闲 30 分钟、连续 100 次计划预览。
- 整理 README 与当前产品状态，明确正式版启用和关闭的模块。

验收门槛：全部非端到端检查通过；正式关闭 Skills/MCP 时不产生相关扫描、网络请求或状态初始化。

#### P1：Skills/MCP 安全启用

- Skills 列表扫描只读取摘要；文件树和深度校验在用户进入详情或主动检查时执行。
- MCP 库在 SQLite 中完成搜索、筛选、排序和分页，前端只保存当前页。
- Skills 与 MCP 计划都具备有效期、数量上限、单次使用和主动取消。
- MCP stdio 探测限制时间、输出大小和进程范围；完成或超时后回收进程与读取任务。
- 页面离开后释放列表、计时器和结果引用；旧请求不能覆盖新请求。
- 先以显式的 Beta 标识启用，达到性能门槛后再移除标识。

验收门槛：空闲期无后台工作；100 次计划预览满足 KR2；大目录和大响应在预算内停止并给出明确错误；写入仍经过预览、冲突检查、备份和回滚。

#### P2：用量行动中心

- 在概览增加“需要处理”区域，统一展示额度阈值、连接器异常、数据过期和异常用量。
- 每个连接器展示：额度状态、Token 状态、最后尝试、最后成功、耗时、错误摘要和单独同步按钮。
- 支持按额度窗口设置提醒阈值，例如 70%、85%、95%；提醒在本地计算并通过应用内通知和托盘展示。
- 使用近期消耗速度估算额度触达时间，所有预测明确标记为估算，并展示使用的数据范围。
- 生成本地周摘要：总 Token、预估费用变化、主要工具、主要模型、额度风险和连接器健康变化。
- Kiro 等估算 Token 与真实 Token 在图表、洞察和导出中保持明确区分。

验收门槛：用户能从一条事项进入唯一的处理页面；单连接器同步不触发其他连接器；提醒不会重复打扰；预测不改变任何原始记录。

#### P3：统一备份、恢复与导出

- 新增“数据管理”页面，展示各数据域的存储位置、记录数和最近更新时间。
- 支持加密导出设置、用量、订阅、账单、片段、Skills/MCP 辅助元数据和应用偏好。
- 密钥库只导出已有密文；CLI 登录凭证和各 Agent 的配置文件不复制进备份。
- 导入前展示变更计划，按数据域选择新增、覆盖或跳过。
- 提供 CSV/JSON 数据导出，便于用户自行分析用量和账单。
- 恢复完成后重新读取数据并进行数量、版本和关联校验。

验收门槛：导出文件不包含明文密钥；同版本往返恢复后核心记录一致；版本不兼容时停止导入并指出具体数据域。

### 7.3 Priority Matrix

| 项目 | 用户价值 | 紧迫度 | 实现成本 | 风险 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| 发布收口与性能基线 | 高 | 最高 | 中 | 低 | P0 |
| Skills/MCP 安全启用 | 高 | 高 | 高 | 高 | P1 |
| 用量行动中心 | 最高 | 高 | 中 | 中 | P2 |
| 统一备份与迁移 | 高 | 中 | 中 | 中 | P3 |
| 新增更多独立工具页 | 低 | 低 | 中 | 中 | 暂不进入路线图 |

### 7.4 Technology

- 保持 Vue 3、Tauri 2、Rust、Nuxt UI 和现有本地优先架构。
- 用量数据继续通过 `UsageStorage` 抽象访问；本阶段不要求迁移现有 Web Storage。
- Skills 和 MCP 配置仍以各 Agent 的配置文件为事实来源；SQLite 只保存目录、收藏和辅助元数据。
- 新增通知、备份和诊断命令时，前后端类型必须保持 camelCase DTO 对齐。
- 所有外部内容都有明确的字节、数量、并发和时间预算。
- 所有会修改文件的操作继续使用计划预览、版本检查、原子写入、备份和回滚。

### 7.5 Assumptions

- 主要用户是单机个人开发者，而不是团队管理员。
- 用户愿意在对应 CLI 中完成登录，并允许应用读取本机会话数据。
- Skills/MCP 的价值足以覆盖完成性能改造的成本。
- 托盘是额度提醒和异常提示的主要入口。
- 用户更在意数据可信、资源稳定和可恢复，而不是短期增加平台数量。

### 7.6 Out of Scope

- 团队账号、组织权限和多人协作。
- 云端账户体系与跨设备实时同步。
- 自动执行代码片段、剪贴板内容、Skill 脚本或 MCP README 命令。
- 自动生成账单记录；计划支出与实际账单继续独立。
- 把 Credits、美元额度或估算 Token 转换成虚构的统一 Token 配额。
- MCP 流量代理和第三方工具调用审计平台。

## 8. Release

### Release 0：稳定基线（1 个迭代）

只完成当前改造、测试更新、性能检查和文档校准。此阶段不启用 Skills/MCP，也不加入新的业务页面。

退出条件：P0 验收全部通过，现有改动形成可独立验证的稳定版本。

### Release 1：Skills/MCP Beta（2 个迭代）

先完成计划生命周期、探测预算、摘要扫描和服务端分页，再开启 Skills/MCP Beta。Beta 阶段收集冷启动、空闲、扫描、搜索、计划和探测指标。

退出条件：达到 KR2，且写入安全语义没有回归。

### Release 2：用量行动中心（2 个迭代）

先交付连接器健康和单独同步，再交付额度提醒、触达时间估算和周摘要。通知默认只针对高优先级事项，由用户配置阈值和静默时段。

退出条件：达到 KR3 和 KR4；估算值与真实值在所有页面保持可区分。

### Release 3：数据管理（1 至 2 个迭代）

交付加密备份、预览恢复、完整性校验和 CSV/JSON 导出。

退出条件：达到 KR5，并完成至少一组全量往返恢复测试。

### 推荐执行顺序

```text
当前改造收口
  → Skills/MCP 资源边界
  → Skills/MCP Beta
  → 连接器健康与单独同步
  → 额度提醒与本地洞察
  → 统一备份与迁移
```

在 Release 2 完成前，不建议新增油价之外的生活工具、更多独立效率页面或团队功能。每个阶段都应先达到退出条件，再进入下一阶段。


### 开发环境模块补充（2026-10-15）

Shell 页面已经具备别名、托管变量、源码编辑与备份入口；当前能力与新版文件操作规范存在差距。其收口及后续规划见 [开发环境管理后续规划](./PRD-开发环境管理后续规划.md)。

- 现有功能正确性收口纳入稳定基线，先补齐值语义、预览、版本冲突、源码与恢复统一提交。
- 基线稳定后，再安排来源诊断与 PATH、项目 `.env`、配置集和环境验证。
- 新增能力与 Skills/MCP、用量行动中心由维护者排定迭代，不自动改变上文整体优先级；保持单一入口，不横向增加独立工具页。
- 上文源码状态与测试数字属于原检查时的历史记录，不能作为 2026-10-15 的测试通过声明。
