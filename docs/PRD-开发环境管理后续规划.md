# PRD - 开发环境管理后续规划

> 日期：2026-10-15
> 状态：基于现有源码和公开产品资料的规划；本文不表示新增功能已经实现或通过运行验收。
> 范围：xlt-workbench 内的 Shell / 开发环境模块。前期保留 `/shell-env`，不新建独立应用。
> 关联：[Shell 环境管理详细规范](./PRD-Shell环境管理.md)、[工作台整体路线图](./PRD-下一阶段功能路线图.md)。

## 1. 摘要

现有 Shell 模块已经具备别名、托管变量、源码编辑、文件校验与备份入口。下一步先补齐现有写入流程和新版规范的差距，再依次交付环境来源与 PATH 管理、项目 `.env`、命名配置集和指定环境验证。

产品定位为“本机开发环境管理器”：帮助个人开发者看清配置来源、可靠修改配置，并验证指定终端或进程中的结果。以 macOS / zsh 为首个适配，不实现通用 Shell 解释器，不接管运行时安装器。

## 2. 角色与决策

| 角色 | 责任 |
|---|---|
| 产品负责人：项目维护者 | 决定范围、阶段进入条件及真实使用验收 |
| 实现负责人：项目维护者 / 开发执行者 | 维护前后端契约、文件操作、解析与资源预算 |
| 验收用户：维护多个 CLI 和项目的个人开发者 | 用真实配置验证来源、迁移、PATH 与环境切换 |

阶段以退出条件推进，不按日期强行开放。整体应用发布基线优先；现有模块的正确性修复可以先做，新能力需在基线稳定后进入。本文不要求重新启用 Skills/MCP，也不改变相关开关。

## 4. 目标与衡量

| 目标 | 阶段验收指标 |
|---|---|
| 现有编辑可信 | R0 全部写入口包含表格、源码和恢复，均通过版本、引号、字节保留与故障注入用例 |
| 来源可解释 | R1 每项都有文件位置或快照身份；动态值标记未求值，不能混为最终值 |
| PATH 可管理 | R1 托管目录可排序，重复与缺失有证据；不能拖动未托管的最终合并列表 |

## 5. 用户与典型任务

### 5.1 维护多个 CLI 的个人开发者

需要定位重复 PATH、同名命令和安装器追加的初始化。例如解释为何 Kimi / Qoder 在一个终端可用、在另一个入口不可用。

### 5.2 同时维护多个项目的开发者

需要比较 `.env.local` 与 `.env.example`，找出缺失 KEY，不把项目配置污染到全局 Shell。

### 5.3 在工作与个人环境间切换的用户

需要按组切换代理、镜像和业务地址，知道哪些变量被覆盖、停用后是什么；不要求后台修改所有进程。

核心约束：单机、本地优先、用户主动操作。GUI 应用、Shell 配置、项目文件、指定进程环境是不同作用范围。

## 6. 用户价值与体验

| 用户任务 | 现状成本 | 规划体验 |
|---|---|---|
| 修改代理 | 找到分散的 export，无法确认覆盖 | 搜索 KEY → 查看来源 → 预览保存 → 复制本次命令 |
| 处理重复路径 | 阅读多段字符串拼接 | 查看来源与出现次数 → 选择可迁移条目 → 预览纳管 |
| 确认 Node 命令来源 | 不知道是 NVM 还是 mise 生效 | 选择观测环境 → 展示搜索顺序及匹配候选，不猜测全局结果 |
| 修改复杂配置 | 源码可编辑但可能覆盖外部变化 | 表格定位源码 → 编辑 → 版本检查 → 差异确认 |
| 比较项目环境 | 手工对照两个文件 | 按 KEY 对齐，缺失与差异突出显示，值默认遮罩 |
| 切换配置集 | 重复粘贴 export | 选择配置集 → 查看覆盖与删除 → 保存生成结果 → 主动应用 |

前期保持一个入口。R1 用“变量 / PATH / 别名 / 诊断”组织主要任务，源码作为来源面板或高级入口保留，备份留在页面操作中。R2 增加项目选择，R3 才增加配置集选择，不为每种能力新增侧边栏一级页面。

示例诊断应写“当前扫描文件含 4 处 local/bin 添加语句”，不能直接写“所有终端一定有 4 个重复目录”。每条诊断有来源、确定性和唯一处理动作；不把静态疑点一律显示成故障。

## 7. 方案、任务与架构

### 7.1 R0：现有能力收口（P0，先做）

| 工作项 | 交付内容 | 依赖 / 验收 |
|---|---|---|
| R0-01 值与解析 | literal / expression / unsupported，alias 与 env 独立转义，区块结构检查 | 引号、美元、反引号、命令替换、尾部空格、条件与 heredoc 样本 |
| R0-02 版本与计划 | Snapshot / entryId、preview / commit / cancel；源码保存和恢复也是操作类型 | 读后外部编辑、同文件并发、旧计划、源码脏状态均不覆盖 |
| R0-03 文件链路 | UUID 临时文件、时间输出预算、权限、元数据、备份清单和恢复 | 无变化不写入；保留 5 份；失败时结果与磁盘实际一致 |
| R0-04 生效体验 | 取消默认整份重载复制，复用 clipboardService，保存与复制分别反馈 | 删除 / 改名清理准确，复制失败不误报保存失败 |
| R0-05 保留现有价值 | 搜索、分组、源码定位、打开文件、备份入口继续可用 | 不移除源码编辑；新增重命名必须按原身份一次提交 |
| R0-06 验证与隔离 | Rust 文件测试、前端契约、diagnostic 回归 | 全部在临时目录 / 无服务环境检查 |

旧 13 个命令迁移到计划 API 时，前后端同一版本更新；完成后移除旧直接写入口，不能保留绕过预览的源码或恢复通道。现有按名称 upsert 改为显式新增 / 编辑，但保留已有合法 alias 名称（包括点和数字开头）；不能因收紧新增规则使旧条目不可删除或无故失效。

已存在的英文说明起始标记识别为明确的旧格式，在一次预览中规范化到新标记；不当作缺失区块再追加。首次创建区块要求用户确认顶层插入锚点，展示前后初始化语句；Kiro pre/post、SDKMAN 等区块保留原顺序，无法证明位置合适时停止该操作。

### 7.2 R1：来源与 PATH（P1，下一项新增能力）

- 新增只读来源模型：file、line/span、kind、owner、certainty、exported、managed；工具名称来自已知标记匹配，未知来源显示未知，不推测所有者。
- 默认读取已注册的两个文件；用户主动选择扩展读取 `.zshenv` / `.zprofile`、`/etc/paths`、`/etc/paths.d`，只读、无管理员修改。
- 仅跟踪经确认的字面量 source 引用；最多深度 3、20 个文件、单文件 1 MiB、总量 4 MiB；循环停止并显示路径。用户选择的文件仍受范围登记和路径检查约束。
- PATH 条目区分 literal、home-relative、variable-expression、dynamic；home-relative 是类型化路径，由后端用已知主目录解析，不使用 eval。
- 检查目录存在性、重复、相对目录及空条目；重复比较先以原文 / 可确定的规范路径判断，不擅自把大小写或软链接视为同一目录。
- 托管 PATH 使用独立条目模型，可增删和排序。只允许对托管目录组排序；外部路径和运行时初始化保持只读。
- R1 写入仍使用 `.zshrc` 顶层托管区，不增加 source hook；生成规范 zsh path 数组操作，说明前置 / 后置规则和去重范围，并测试重复应用的幂等性。
- 不宣称能约束后续 NVM / mise / SDKMAN 的修改；快照中的最终 PATH 单独只读展示。
- “纳入管理”只处理经静态证明的简单字面量定义：移除原定义与新增托管条目必须在同一文件计划内完成；跨文件迁移和任意表达式拆解不在 R1。
- 目录检查不是程序健康检查；不得为了显示版本而自动执行目录内的程序。

验收样本采用用户提供的复杂 `.zshrc` 的脱敏副本：准确展示 local/bin 多处添加、Qoder 去重语句和运行时区块；不重排 Kiro / SDKMAN / mise，不自动执行 starship 或 mise。

### 7.3 R2：项目 `.env`（P2）

- 用户主动注册项目根目录和选择 `.env*` 文件，允许自定义环境名称、颜色与说明；不默认扫描全盘或 node_modules。
- 提供 Key / Value / Comment 编辑、源码查看、来源位置、跨环境按 KEY 对齐比较、生成剥离值的 `.env.example`。
- 明确首期 dotenv 方言：单行键值、空值、注释、规定引号；插值和多行定义显示原文与支持状态，不假定与 zsh 语法相同。
- 文件仍是配置事实来源，元数据只保存项目登记、环境名称和 UI 偏好；编辑复用版本与备份流程，不能用 zsh 校验 `.env`。
- 目录枚举深度最多 3、文件候选最多 100、单文件 1 MiB；按需读文件，不常驻索引秘密值。目录排除规则可见。
- 值默认掩码；搜索默认覆盖 KEY、注释、文件名，搜索值需本次主动开启且不保存查询内容。
- 文件归类为 production 不代表已部署；创建 / 选择 `.env` 不代表任何进程已加载该文件。

### 7.4 R3：命名配置集（P3，依赖 R1 / R2）

- 初期模型：基础配置 + 一个活动配置集；多个集可以保存，只能同时启用一个。
- 每个集合绑定作用范围：用户 Shell 或一个项目；禁止暗中把项目变量升级为全局。
- 在应用专属、版本化 JSON 中保存声明配置；当前托管区是生成结果，外部文件仍归原所有者。项目 `.env` 不自动改为生成物，需单独选择托管目标。
- 允许逐 KEY 的 set / remove；预览展示未设置与空字符串的区别、来源、覆盖和移除。
- 切换 / 停用根据基础声明重新生成，只替换受管区域；不能用恢复旧整文件快照实现停用。
- 保存 activeProfile 与生成文件存在多对象一致性要求：提交日志记录 preimage / postimage 和激活状态；启动检测中断后展示待处理状态，证明一致后才允许继续切换，不声称多个 rename 天然原子。
- 手改生成区、外部文件冲突、秘密引用缺失时停止提交，供用户检查差异；不得静默覆盖。
- “活动”只表示已保存的配置选择；另显示目标文件版本和终端应用状态，不能据此承诺现有终端已更新。

### 7.5 R4：环境验证与秘密引用（P4，按实际需求）

- 优先提供用户在指定终端运行的最小采集命令，采集选定 KEY、PATH、工作目录和 shell 标识；默认不采集所有秘密。
- 外部输入按有界数据解析，设置 256 KiB 上限，禁止 eval；快照内存保存，默认不落盘。
- 工作台自身环境单独标记；指定 PID 的采集只读用户主动选择的进程，明确权限、采集时间和“启动环境可能不是最新内部状态”的限制。
- 命令解析先对选定快照的 PATH 枚举候选位置；区分 alias、function、shim 与可执行文件，不能只依据文件名宣称其真实版本。
- 用户主动执行版本探测时，用固定命令表、参数数组、5 秒、64 KiB 输出预算；任意用户命令不进入探测。
- 项目运行先只作用于应用主动创建的子进程，不改变系统全局环境；不新增自动目录 hook。
- 秘密复用现有 vault 的稳定 ID，配置集只存引用；临时解锁后才取值。Keychain 适配另行评估，不同时实现两套秘密存储。
- 揭示、复制和导出是明确动作；落入 Shell 或 `.env` 后是明文。明文值不写诊断日志、版本索引或遥测。

### 7.6 架构和预算

| 层 | 责任 |
|---|---|
| Source adapter | zsh / dotenv 读取、来源范围、支持能力，不运行配置 |
| Domain model | Snapshot、Entry、PathEntry、Diagnostic、Profile、Observation |
| Change pipeline | 候选差异、版本检查、备份、提交、恢复；领域格式校验由 adapter 提供 |
| UI / observation | 按作用范围展示数据，区分静态定义、生成配置、运行快照 |

先将 `shellenv.rs` 拆为 types / parser / serializer / files / plan / commands；到 R2 第二个真实适配落地后，再抽取公共文件能力。前端将数据、草稿、预览、源码脏状态按职责拆分，避免继续把所有逻辑堆入当前大页面。

沿用详细 PRD 的计划 5 分钟、最多 16 个、单次消费规则；页面卸载主动取消，命令入口清理过期。所有 IO / 校验在阻塞线程池；诊断按需运行，资源有界，不在启动时全量扫描。原有 Skills/MCP 计划和状态不直接复用。

源码编辑是现有正式能力，必须纳入相同版本 / 预览机制；它允许用户主动修改复杂文本，但不扩大结构化编辑器的解析承诺。

### 7.7 首个迭代任务顺序

1. 固化当前三 Tab、13 命令和旧区块格式的回归样本。
2. 完成 B01 / B02 的值和解析契约，保留现有合法名称。
3. 实现 Snapshot、变更操作、preview / commit / cancel，源码与恢复同时接入。
4. 收口临时文件、备份、格式、元数据、预算和并发；故障注入验证。
5. 前端差异确认、脏源码互斥、状态文案和剪贴板独立反馈。
6. 运行无服务检查并进行用户主动启动的桌面验收；通过后开始 R1。

### 7.8 非目标与待验证假设

不规划：团队权限、云同步、运行时下载安装、全自动整理 `.zshrc`、系统级 launchd 注入、MCP 网关、远程主机、多 Shell 同时落地、AI 自动执行修复。

需要验证：用户是否愿意迁移简单定义到托管区；PATH 诊断是否比配置集更高频；dotenv 方言能否覆盖主要项目；用户主动采集指定终端环境是否足够易用。每阶段用真实任务验证，不以新增 Tab 数量衡量成功。

## 8. 发布、验收与整体衔接

| 发布 | 相对规模估计 | 进入条件 | 退出条件 |
|---|---|---|---|
| R0 可信编辑 | 约 2 个迭代，解析和文件语义可能增加工作量 | 冻结现有行为与样本，按实际差距实施 | B01—B10 全部闭环，三类写入口共用计划；无服务检查通过 |
| R1 来源与 PATH | 约 2 个迭代 | R0 完成、整体应用基线稳定 | 用户样本诊断正确、托管排序幂等、外部区块不变 |
| R2 项目环境 | 约 1—2 个迭代 | 公共写入链路已稳定 | `.env` 无损往返、比较准确、不执行文件、范围与扫描预算有效 |
| R3 配置集 | 约 2 个迭代 | R1 / R2 的作用范围明确 | 覆盖、停用、漂移和中断一致性用例通过 |
| R4 验证与引用 | 单独评估后分批 | 用户实际需要运行环境对比 | 快照范围准确、秘密不意外持久化、子进程资源可回收 |

估计以一名熟悉仓库的开发者持续投入为假设，不构成日期承诺。每个阶段可独立发布；未通过退出条件，不开始下一阶段的配置写入能力。

### 8.1 检查与样本

- Rust：纯解析、序列化、临时目录文件链路、恢复、计划、预算和故障注入。
- 前端：invoke 契约、浏览器不触发 IPC、预览失效、保存 / 复制独立结果、路由与 diagnostic 隔离。
- 会话：隔离 zsh 子进程验证字面量、alias 调用时机、删除清理与 PATH 幂等；不 source 用户真实配置。
- 样本：用户复杂 `.zshrc` 脱敏副本、重复 / 缺失标记、引号与 heredoc、CRLF、无末尾换行、同秒备份、外部修改、源码脏状态、dotenv 插值与秘密掩码。
- 每次验收记录实际执行命令与结果；历史文档中的测试通过数不能当作当前结果。

实现后的建议检查为 `pnpm typecheck`、专属 `smoke-shell-env.mts`、`smoke-diagnostic.mts`、`cargo test shellenv::tests`、适配重构后的相关 Rust 测试与 `cargo check`。新增脚本落地后再纳入 package.json，不将规划命令视为当前已经存在。

本轮不启动任何前端或桌面服务。后续用户自行运行 `pnpm tauri dev` 做桌面验收；纯浏览器 `pnpm dev` 不提供原生文件能力。

### 8.2 与工作台整体路线图的关系

整体发布基线优先；已有 Shell 的正确性问题作为现有功能收口处理。R1 之后的开发环境能力是新的工作流增量，需由维护者与 Skills/MCP、用量行动中心排定迭代，不默认抢占已确定的整体阶段。

前期单一 `/shell-env` 入口，R1 可改展示名为“开发环境”并保持路由兼容。统一备份阶段优先纳入项目登记、配置集声明和元数据；是否包含用户配置与明文秘密必须另行明确选择，不改变整体备份默认排除凭证的原则。
