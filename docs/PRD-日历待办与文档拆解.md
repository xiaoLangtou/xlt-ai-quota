# XLT Workbench 日历、待办与文档拆解 PRD

> 文档状态：待评审  
> 适用产品：XLT Workbench 桌面端  
> 版本范围：V1  
> 原型：[calendar-todos-prototype.html](./prototype/calendar-todos-prototype.html)

## 1. 摘要

日历与待办功能把日程、任务和需求计划放进同一个本地工作区。用户可以直接创建任务，也可以上传文档或粘贴内容，让 AI 拆成可确认的待办，再批量加入日历。

文档拆解后台读取 Git 报告已经保存的 AI 服务商、模型和 API Key。页面不展示、不编辑也不重复保存这些配置。

## 3. 背景

### 3.1 当前问题

XLT Workbench 已提供 AI 用量、Git 报告、剪贴板、代码片段和密钥库，但缺少统一的计划执行入口。用户从 PRD、会议纪要或需求说明中得到工作项后，仍需手工整理任务、估算时间并录入其他日历或待办工具。

当前 Git 报告已经保存 MiniMax、Kimi、DeepSeek 的服务商、模型和 API Key。文档拆解可以直接使用该能力，不要求用户再次填写相同配置。

### 3.2 产品原则

1. **本地优先**：日历、待办和拆解结果只写入本机应用数据库。
2. **用户确认后写入**：AI 只生成建议，用户确认后才创建待办和日历事件。
3. **配置单一来源**：AI 配置继续由 Git 报告管理，文档拆解只读取配置。
4. **输入来源清晰**：上传文档与复制粘贴是两个明确入口。
5. **日历和待办互通**：有计划日期的待办同时显示在日历中，完成状态保持一致。
6. **隐私边界明确**：用户点击“开始拆解”后，系统才向已配置的 AI 服务商发送提取后的文档正文。

### 3.3 V1 范围

V1 包含：

- 月、周、日三种日历视图。
- 今日待办、全部待办和状态筛选。
- 日历日期右键快速创建待办。
- 待办与日历事件的双向关联。
- Markdown、TXT、DOCX 和 PDF 文档导入。
- 复制粘贴文本拆解。
- 复用 Git 报告 AI 配置并生成结构化待办。
- 用户编辑、选择和批量确认拆解结果。

V1 不包含：

- Google Calendar、Apple Calendar 或 Outlook 同步。
- 多人协作、分享、评论和权限。
- 重复日程和复杂循环规则。
- 邮件、系统通知和跨设备提醒。
- 文档拆解历史和原始文档归档。
- 自动执行代码、命令或拆出的任务。

## 4. 目标

### 4.1 产品目标

- 为个人开发者提供一个本地的“需求输入 → 任务确认 → 日历执行”闭环。
- 减少从文档手工提取任务、排期和验收标准的时间。
- 复用现有 AI 配置，避免重复配置和凭据分散。
- 让用户在日历与待办之间保持一致的计划状态。

### 4.2 用户目标

- 用户可以在 10 秒内为指定日期创建一条待办。
- 用户可以从文档或粘贴内容生成结构化待办。
- 用户可以在写入前修改标题、日期、优先级、工作量和验收标准。
- 用户可以在同一页面查看当天日程、未完成事项和完成进度。

### 4.3 关键结果

| 关键结果 | V1 目标 | 验证方式 |
| --- | --- | --- |
| 指定日期快速创建待办的中位操作时间 | 不超过 10 秒 | 人工任务测试。 |
| 文档提交到展示拆解结果的成功率 | 不低于 95% | 支持格式的标准样本文档测试。 |
| AI 结果通过结构校验的比例 | 不低于 98% | 记录结构校验结果，不记录文档正文。 |
| 批量确认后任务与日历事件一致率 | 100% | 数据库事务和集成测试。 |
| API Key 在文档拆解界面的展示次数 | 0 | UI、日志和快照检查。 |
| 用户确认前写入正式待办的数量 | 0 | 端到端测试。 |

## 5. 市场与用户场景

### 5.1 核心用户

核心用户是使用多个 AI 编程工具的个人开发者、技术负责人和独立产品开发者。他们经常从 PRD、会议记录、Issue 说明和技术方案中整理任务，并希望数据留在本机。

### 5.2 核心任务

| 用户任务 | 当前障碍 | 目标结果 |
| --- | --- | --- |
| 安排一条临时任务 | 需要离开当前页面并填写完整表单 | 在目标日期右键，填写标题和时间后创建。 |
| 查看今天需要完成的工作 | 日程和待办分散 | 日历旁固定展示今日待办和完成进度。 |
| 从 PRD 提取开发任务 | 手工阅读、归类和复制 | 上传文档后得到分组、依赖和排期建议。 |
| 从聊天内容整理计划 | 需要先保存成文件 | 直接粘贴文本并开始拆解。 |
| 修改 AI 生成结果 | AI 结果可能不符合实际安排 | 写入前逐项选择和编辑。 |

### 5.3 使用约束

- 功能只在 Tauri 桌面端完整可用。
- 文档可能包含中文、英文、代码块、表格和列表。
- 单个文件最大 20 MB，提取后的正文最大 60,000 个字符。
- 一次拆解最多生成 50 条待办。
- AI 服务需要 Git 报告中已经保存有效的服务商、模型和 API Key。
- 用户可能在离线状态下管理已有日历和待办，但文档拆解需要网络。

## 6. 价值主张

### 6.1 统一计划入口

用户不需要在日历、待办和文档之间反复复制内容。计划日期、完成状态和来源信息在一个工作区内保持一致。

### 6.2 降低需求整理成本

文档拆解把长文档转换成可执行任务，并同时给出任务分组、依赖、预估工作量和验收标准。用户把时间用在确认和调整上，而不是重复录入。

### 6.3 减少配置重复

文档拆解读取 Git 报告已有的 AI 配置。用户不需要在新页面再次选择服务商、模型或输入密钥，产品也不会创建第二份凭据。

### 6.4 保留用户控制权

AI 输出只作为草稿。用户可以取消选择、修改内容和调整日期，确认操作是正式写入数据的唯一入口。

## 7. 解决方案

### 7.1 信息架构

主导航的“工作”分组新增“日历与待办”，放在“Git 报告”之前。页面使用左侧日历和右侧今日待办的双栏结构。

```text
工作
├─ 日历与待办
│  ├─ 日 / 周 / 月视图
│  ├─ 今日待办
│  ├─ 全部待办
│  └─ 文档拆解
└─ Git 报告
   └─ AI 配置来源
```

AI 配置仍由 Git 报告页面管理。日历与待办页面不增加 AI 设置入口。

### 7.2 核心用户流程

#### 7.2.1 手工创建待办

```text
选择日期
  → 右键日期格
  → 输入标题、时间和分类
  → 创建待办
  → 日历和待办列表同时显示
```

#### 7.2.2 文档拆解

```text
打开“文档拆解”
  → 上传文档或粘贴文本
  → 点击“开始拆解”
  → 后台读取 Git 报告 AI 配置
  → 提取正文并调用 AI
  → 展示结构化待办草稿
  → 用户编辑和选择
  → 批量创建待办及日历事件
```

#### 7.2.3 完成待办

```text
勾选待办
  → 状态变为已完成
  → 日历中的关联项同步显示完成状态
  → 今日完成进度重新计算
```

### 7.3 日历功能

#### 7.3.1 视图

- 月视图展示六周网格和每个日期的前三条事项，更多事项显示数量。
- 周视图展示七天时间轴，事件以 15 分钟为最小调整单位。
- 日视图展示单日时间轴和全天事项区。
- 小于 820 px 的内容区域显示三日窗口，不压缩成不可读的七列。
- “今天”按钮回到当前日期。
- 前后箭头按当前视图移动一天、一周或一个月。

#### 7.3.2 快捷操作

- 右键当月日期格打开快速创建菜单。
- 快速创建字段包括标题、时间和分类。
- 双击空白时间区域打开完整创建表单。
- 拖动事件修改时间或日期，结果立即写入本地数据库。
- 拖动事件底边修改持续时间，每次调整以 15 分钟为单位。

#### 7.3.3 事件显示

事件按分类使用稳定颜色。V1 内置“产品迭代”“需求拆解”“个人”三种分类标识，用户数据中只存分类标识，不存样式值。

有计划日期但没有具体时间的待办显示为全天事项。有具体时间的待办显示在对应时间段。

### 7.4 待办功能

#### 7.4.1 字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 标题 | 是 | 1–160 个字符。 |
| 描述 | 否 | 最大 4,000 个字符。 |
| 状态 | 是 | `open` 或 `done`。 |
| 优先级 | 是 | `high`、`medium` 或 `low`。 |
| 计划日期 | 否 | 本地日期，格式为 `YYYY-MM-DD`。 |
| 计划时间 | 否 | 本地时间，格式为 `HH:mm`。 |
| 预估工作量 | 否 | 分钟数，最小 30 分钟。 |
| 分类 | 是 | `work`、`planning` 或 `personal`。 |
| 验收标准 | 否 | 最多 6 条，每条不超过 300 个字符。 |
| 依赖任务 | 否 | 只允许引用同一批次或已有任务。 |
| 来源 | 是 | `manual` 或 `document`。 |

#### 7.4.2 今日待办

- 右侧面板展示计划日期为今天的待办。
- 待办按上午、下午和未定时间分组。
- 面板支持全部、未完成和已完成筛选。
- 完成进度按“已完成数量 ÷ 今日总数”计算。
- 快速输入框创建没有具体时间的今日待办。

#### 7.4.3 全部待办

V1 在同一页面提供可切换的全部待办面板。用户可以按状态、优先级、分类、计划日期和来源筛选，并可以编辑或删除单条待办。

删除关联待办时，系统在同一个事务中删除对应日历事件。删除普通日历事件不会影响其他待办。

### 7.5 文档输入

#### 7.5.1 上传文档

- 支持选择文件和拖拽文件。
- 支持 `.md`、`.txt`、`.docx` 和 `.pdf`。
- 文件最大 20 MB。
- Rust 后端在本机读取并提取正文。
- 系统不保存原始文件副本。
- 系统不把本机文件路径发送给 AI 服务商。

#### 7.5.2 复制粘贴

- 文本框支持多行内容、Markdown 和代码块。
- 页面实时显示字符数。
- 内容为空时，“开始拆解”按钮不可用。
- 内容超过 60,000 个字符时，页面阻止提交并提示用户缩短内容。

#### 7.5.3 输入切换

上传与粘贴是互斥输入。用户切换输入方式时，页面保留当前内容，实际提交只读取当前选中的来源。

### 7.6 AI 配置复用

#### 7.6.1 配置来源

系统从 `xlt.daily-report.preferences` 读取：

- `ai.provider`
- `ai.model`
- `aiApiKeys[provider]`

文档拆解页面不显示服务商、模型、密钥状态或配置来源。用户不能在该页面修改 AI 配置。

#### 7.6.2 配置读取时机

`documentDecompositionService.generate()` 在用户点击“开始拆解”时读取最新配置。Git 报告页面保存的新配置从下一次拆解开始生效。

配置缺失或不完整时，系统不发送文档内容。页面显示“请先在 Git 报告中完成 AI 配置”，并提供前往 Git 报告页面的操作。

#### 7.6.3 凭据约束

- 新功能不创建新的 API Key 存储键。
- API Key 不进入 Pinia、URL、日志、错误消息或拆解结果。
- 前端只在调用期间把 API Key 传给 Tauri 命令。
- Rust 调用完成后不持久化请求体、响应正文或 API Key。

### 7.7 AI 拆解契约

#### 7.7.1 输入

```ts
interface DocumentDecompositionRequest {
  sourceName: string
  content: string
  provider: "minimax" | "kimi" | "deepseek"
  model: string
  apiKey: string
  currentDate: string
}
```

`sourceName` 只使用文件名或“粘贴内容”，不包含本机目录。`content` 是本机提取后的纯文本。

#### 7.7.2 输出

```ts
interface DocumentDecompositionResult {
  summary: string
  assumptions: string[]
  groups: Array<{
    id: string
    title: string
    tasks: Array<{
      id: string
      title: string
      description: string
      priority: "high" | "medium" | "low"
      estimatedMinutes: number | null
      suggestedDate: string | null
      suggestedTime: string | null
      dependencyIds: string[]
      acceptanceCriteria: string[]
    }>
  }>
}
```

#### 7.7.3 生成规则

- 每条任务必须可以独立确认和完成。
- 标题使用动词开头，明确产出。
- 任务按功能模块分组。
- 依赖只能引用结果内存在的任务 ID。
- 建议日期不得早于当前日期，也不得超过当前日期后 180 天。
- 预估工作量使用 30 分钟的整数倍。
- 验收标准必须可观察和可验证。
- 输出最多包含 50 条任务。
- AI 必须返回符合约定的 JSON，不输出 Markdown 包裹文本。

### 7.8 拆解结果确认

#### 7.8.1 结果摘要

结果区展示：

- 模块数量。
- 待办数量。
- 总预估工作量。
- AI 识别出的前提假设。

#### 7.8.2 逐项编辑

用户可以：

- 选择或取消选择任务。
- 修改标题和描述。
- 修改优先级、日期、时间和预估工作量。
- 修改验收标准。
- 查看依赖关系。

至少选择一条任务后，“创建待办”按钮才可用。

#### 7.8.3 批量写入

确认操作在一个数据库事务中完成：

1. 创建选中的待办。
2. 为包含计划日期的待办创建关联日历事件。
3. 将拆解结果中的临时依赖 ID 转换为正式任务 ID。
4. 写入任务依赖关系。
5. 返回新建数量和任务 ID。

事务中任一步骤失败时，本次确认不写入任何正式任务或日历事件。

| `document_decomposition_generate` | 调用 AI 并返回结构化草稿。 |
| `document_decomposition_commit` | 事务写入选中的待办、事件和依赖。 |

`daily_report_generate` 当前包含日报 Prompt 和供应商请求。开发时将供应商地址、认证头、响应读取和 `<think>` 内容清理提取为共享 Rust 模块，日报与文档拆解分别维护自己的 Prompt 和响应校验。

### 7.12 状态与错误

| 状态 | 页面行为 |
| --- | --- |
| 未选择文件且没有粘贴内容 | 禁用“开始拆解”。 |
| AI 配置缺失 | 不发送内容，提示前往 Git 报告完成配置。 |
| 文件格式不支持 | 显示支持的格式，不读取文件。 |
| 文件超过限制 | 显示文件大小限制，不读取文件。 |
| 正在提取正文 | 禁用输入切换和提交按钮。 |
| 正在拆解 | 显示进度状态，禁止重复提交。 |
| AI 返回结构无效 | 显示结构校验错误，不展示未校验内容。 |
| 正在批量创建 | 锁定结果编辑，避免确认内容变化。 |
| 创建成功 | 关闭抽屉，刷新日历与今日待办并显示数量。 |

### 7.13 隐私与安全

- 用户点击“开始拆解”前，应用不发送文档内容。
- 页面在提交按钮附近说明正文会发送给 Git 报告中配置的 AI 服务商。
- 请求只包含提取后的正文、模型名和生成指令。
- 请求不包含本机绝对路径、Git 项目列表、作者配置或其他本地数据。
- 文件读取必须限制在用户明确选择的路径。
- DOCX 和 PDF 解析必须限制文件大小、页数和解压后总大小。
- AI 响应按数据处理，不执行其中的代码、命令或链接。
- 日志只记录耗时、供应商、模型、结果状态和任务数量，不记录正文、密钥和完整响应。

### 7.14 性能要求

| 场景 | 目标 |
| --- | --- |
| 打开月视图 | 本地有 2,000 条事件时，500 ms 内可交互。 |
| 切换月 / 周 / 日 | 200 ms 内完成本地视图更新。 |
| 勾选待办 | 100 ms 内更新界面。 |
| 打开文档拆解抽屉 | 150 ms 内可交互。 |
| 读取 5 MB TXT / Markdown | 500 ms 内完成。 |
| 批量写入 50 条任务 | 500 ms 内完成本地事务。 |

AI 网络耗时不计入本地性能指标。请求必须设置连接和总时长限制，并允许用户主动取消。

### 7.15 埋点与可观测性

V1 只记录本地运行指标，不上传内容：

- 日历视图切换次数。
- 手工创建待办数量。
- 文档拆解请求次数、耗时和结果状态。
- 输入来源类型：文件或粘贴。
- AI 返回任务数量。
- 用户最终确认的任务数量。
- 批量写入耗时和结果状态。

### 7.16 验收标准

#### 日历

- [ ] 用户可以切换日、周、月视图。
- [ ] 用户可以回到今天并按视图前后导航。
- [ ] 用户可以右键当月日期创建待办。
- [ ] 用户可以拖动事件修改日期和时间。
- [ ] 有日期的待办显示在对应日历位置。
- [ ] 完成待办后，日历项同步显示完成状态。

#### 待办

- [ ] 用户可以新建、编辑、完成和删除待办。
- [ ] 今日面板支持全部、未完成和已完成筛选。
- [ ] 完成进度与当前任务状态一致。
- [ ] 删除待办会同时删除关联日历事件。
- [ ] 刷新或重启应用后，本地数据保持不变。

#### 文档拆解

- [ ] 用户可以选择或拖拽支持的文档。
- [ ] 用户可以切换到复制粘贴输入。
- [ ] 页面不展示服务商、模型、API Key 或“已读取配置”状态。
- [ ] 点击“开始拆解”时读取 Git 报告最新 AI 配置。
- [ ] 配置缺失时不发送文档内容。
- [ ] 拆解结果符合结构契约并通过字段校验。
- [ ] 用户可以编辑和取消选择生成的任务。
- [ ] 用户确认前不创建正式任务。
- [ ] 批量确认在一个数据库事务中完成。

#### 隐私

- [ ] API Key 不出现在界面、URL、日志和错误消息中。
- [ ] 发送给 AI 的内容不包含本机绝对路径。
- [ ] 原始文档不写入应用数据库。
- [ ] AI 返回内容不会被执行。

### 7.17 测试计划

#### 前端单元测试

- 日历范围计算和视图导航。
- 今日待办分组和完成进度。
- 右键日期创建数据映射。
- 文档输入方式切换和字符限制。
- Git 报告 AI 配置读取。
- 拆解结果选择、编辑和确认请求映射。

#### Rust 单元测试

- 文件扩展名、大小和路径校验。
- Markdown、TXT、DOCX 和 PDF 正文提取。
- 拆解 Prompt 生成。
- AI JSON 结构校验。
- 日期、依赖和任务数量限制。
- 批量写入事务和回滚。

#### 集成测试

- 读取 Git 报告配置并完成一次拆解。
- 从上传文档生成并确认任务。
- 从粘贴文本生成并确认任务。
- 确认后同时刷新日历和待办。
- 配置缺失、文件不支持、网络错误和结构错误场景。
