# 禅道待办工作流与智能辅助产品规划

版本：讨论稿 v1.0  
日期：2026-10-27  
状态：需求规划与第一阶段开发记录；已实现范围见第 8 节，未列入该记录的能力仍为规划。

## 1. 概述

本次进化围绕一个目标：**打开待办，就能知道先处理什么，并在这里完成处理。**

产品以“发现 → 理解 → 安排 → 处理 → 跟进”为主线，把待办排序、详情操作、同步反馈和个人计划连接起来。智能辅助贯穿这条主线，帮助用户判断重点、理解问题和准备行动；所有建议都提供依据，涉及禅道写入的内容由用户确认后提交。

## 2. 参与角色

当前按职责定义参与角色，具体负责人在实施前确定。

| 角色 | 主要职责 | 重点确认事项 |
| --- | --- | --- |
| 产品负责人 | 确认范围、优先级和使用体验 | 首版功能与验收结果 |
| 日常使用者 | 验证真实任务和 Bug 的处理流程 | 排序是否合理、建议是否有用 |
| 研发负责人 | 实现界面、数据同步和远端操作 | 接口能力、状态核实、性能 |
| AI 能力负责人 | 设计输入范围、结果结构与评估 | 摘要准确性、引用依据、调用成本 |

## 3. 背景与问题

禅道待办已经具备同步、列表与看板、详情阅读及部分处理能力。近期优化集中在布局、详情平铺、动态字号和可调分栏，后续需要让这些入口组成连贯的工作过程。

用户仍需自行判断哪些事项最紧急，阅读长描述和多次转交记录，并在处理后重新寻找下一项。同步完成后，新增、重新激活、转交和新回复也需要用户逐条识别。

智能化的价值来自这些具体工作：缩短判断与阅读时间，指出值得关注的变化，准备可编辑的处理内容，并把建议转化为用户可执行的操作。

## 4. 目标与衡量方式

### 4.1 产品目标

- 用户进入页面后，能快速理解待处理事项的顺序及原因。
- 用户能在详情内完成常用处理，并连续进入下一项。
- 用户能识别同步后的关键变化，持续跟进自己负责或已经转交的事项。
- 用户能把禅道事项加入个人计划，并在日历中安排时间。
- 用户能核对 AI 结论的来源，自主决定是否采用建议。

### 4.2 验收与效果指标

以下为建议目标，需要在试用期采集基线后校准；目前没有实际测量结果。

| 指标 | 测量方法 | 建议目标 |
| --- | --- | --- |
| 首项选择耗时 | 比较打开待办至选定第一项的时间 | 试用两周后，中位数较基线下降 30% |
| 连续处理效率 | 对同类五项事项记录完成处理所需的页面操作数 | 工作流首版试用后，较基线减少 30% |
| 摘要事实准确性 | 抽取至少 30 条不同类型事项，对照描述和动态人工核对 | 有事实依据的陈述占比达到 95%，关键状态与指派人无错误 |
| 建议可追溯性 | 检查摘要、推荐理由和下一步建议 | 每条事实性结论都关联可核对的来源 |
| 远端写入可靠性 | 覆盖成功、拒绝、超时和回读失败场景 | 未核实成功时不显示处理成功，不自动重发写请求 |

## 5. 使用场景与约束

### 5.1 核心使用场景

| 场景 | 用户需要 | 产品提供的帮助 |
| --- | --- | --- |
| 早晨开始工作 | 决定今天先做什么 | 有理由的处理排序、今日建议、加入今日计划 |
| 接手复杂事项 | 快速理解问题和上下文 | 智能摘要、关键动态定位、待确认问题 |
| 连续处理 Bug | 减少重复导航和输入 | 评论与状态操作、处理后下一条、草稿辅助 |
| 同步后检查变化 | 识别新增回复和状态变化 | 变化摘要、未读标记、变化列表 |
| 跟进已转交事项 | 知道事项是否继续推进 | 已转交视图、最近动态、关注变化 |
| 安排一天工作 | 给事项分配时间和精力 | 个人排期、预计投入、日历时间块 |

### 5.2 产品约束

- 复用现有桌面应用、禅道连接和设置中的 AI 服务商及自定义模型配置。
- 禅道状态、指派人等远端事实以禅道核实结果为准；个人排期与远端状态分别保存。
- 页面适配大小屏，保持可拖动分栏和小屏聚焦详情；描述、动态和附件继续平铺阅读。
- 本规划不包含自动提交评论、自动转交或自动解决事项，也不包含自主修改业务代码。
- 本文不预设禅道评论接口和所有历史字段均可用，实施前需要验证接口及权限。

## 6. 用户价值

| 工作环节 | 工作流能力 | 智能辅助 | 用户收益 |
| --- | --- | --- | --- |
| 发现 | 待我处理排序、常用视图 | 今日处理建议 | 更快确定关注重点 |
| 理解 | 连续详情、动态与附件 | 问题与进展摘要 | 减少重复阅读 |
| 安排 | 今日计划、时间与预计投入 | 建议加入计划并解释原因 | 将建议转化为可执行安排 |
| 处理 | 评论、指派、解决、开始、完成 | 下一步建议、评论和处理说明草稿 | 缩短操作与输入过程 |
| 跟进 | 同步变化、未读与已转交视图 | 需要关注的变化摘要 | 更容易发现后续进展 |

## 7. 解决方案

### 7.1 页面与主流程

待办页面顶部保留同步信息和来源切换。工作区增加可收起的“今日处理建议”，下方继续使用工作视图、搜索筛选及列表或看板；打开事项后进入详情阅读和处理区。

详情按“事项信息与操作 → 智能摘要 → 描述 → 动态 → 附件”排列。AI 操作就近放在相关区域，生成过程有明确状态，长内容按用户操作展开。

典型流程：

1. 用户打开待办，查看待我处理的排序和今日建议。
2. 用户打开事项，通过摘要理解问题，并点击依据定位原始动态。
3. 用户立即处理，或将事项加入今日计划并安排时间。
4. 用户编辑评论或处理说明，确认后提交。
5. 系统回读核实结果，用户继续处理下一条。
6. 后续同步汇总变化，用户查看需要关注的事项并标记已读。

### 7.2 有解释的处理排序

“待我处理”提供默认的“建议处理顺序”。首版采用明确、可解释的规则，按以下分组依次展示：逾期未处理、今日计划、高优先级、其他未处理事项。

同一事项符合多个条件时进入最高顺序分组，同时显示所有适用的原因标签。分组内按优先级、计划或截止时间、最近更新时间排列，最后使用稳定标识保证相同条件下顺序稳定。

列表展示逾期天数、当前指派人和最近更新时间。逾期优先根据明确截止日期判断；只有个人计划日期时，显示“计划已过期”，避免混淆业务截止时间。缺少相关日期时不生成逾期判断。

用户可以切换最近更新等常规排序。AI 今日建议独立呈现；刷新建议不会悄悄打乱用户正在浏览的列表。

### 7.3 完整处理区与连续处理

详情集中承载评论、指派、Bug 解决、任务开始和完成等操作，按钮根据事项类型、实时状态和用户权限显示。

评论支持直接编写，也支持从 AI 草稿进入编辑。提交成功后刷新动态；未核实结果时展示明确状态，避免重复提交。

提供“处理后进入下一条”选项。开启后，系统仅在操作已回读核实、且事项已离开当前待处理集合时，按提交前可见顺序进入下一个有效事项；普通评论不触发跳转。没有下一条时展示本轮处理完成状态。

处理和返回过程保留搜索、筛选、排序、列表位置与分栏宽度。选中事项处理后即使移出筛选结果，也先完成结果反馈，再执行跳转。

### 7.4 智能摘要与下一步建议

用户在详情中主动生成摘要，输入包括事项描述、当前状态、指派信息和选定范围内的动态。摘要使用固定结构：

- **当前事项**：当前 Bug 或任务的主要内容。
- **目的**：事项要解决的问题或要达到的目标。
- **前端涉及的改动**：资料明确提及的界面或客户端改动。
- **后端涉及的改动**：资料明确提及的服务、接口或数据改动。

Bug 的摘要另附已读取的禅道历史记录，直接展示原始动态。资料没有明确说明目的或改动时，相应栏目说明信息不足，不猜测实现。

事实性结论关联描述段落或具体动态，点击后定位原文。建议明确标注为建议；原文没有的信息保留为待确认，不推断为已发生事实。动态保留稳定引用标识，避免排序变化后引用错位。

摘要显示生成时间及数据截至时间。描述、状态、指派或动态变化后标记“内容已更新”，由用户重新生成；相同内容重复打开复用本机已生成结果。附件正文和图片识别不进入首版输入范围。

后续可在处理流程中提供下一步建议，并生成评论或处理说明草稿。草稿保留编辑入口，用户确认具体内容与操作目标后才提交禅道。

### 7.5 今日处理建议

用户主动生成当天建议，系统综合待处理事项的优先级、日期、最近变化及个人排期，推荐默认最多五项，并允许调整数量。

每项包含事项编号、标题、建议原因、相关证据和建议动作，提供“打开详情”“加入今日计划”“本次忽略”入口。AI 不凭空填写预计工时，也不自动改变事项状态或排期。

首版使用已同步的列表信息和本机已有详情，不为生成建议批量拉取所有事项详情。每次调用明确展示候选数量、详情覆盖情况和数据截至时间；信息不足的建议注明缺少的依据。

当天内容和输入范围相同可复用结果。用户可以手动更新；日期或候选内容变化后提示结果已过期。

### 7.6 同步变化与智能关注

同步结果同时展示本次变化摘要及逐条列表，例如新增、重新激活、转交和其他状态更新。一项事项可以发生多种变化，界面分别标明“变化事件数”和“涉及事项数”，避免误读合计。

变化按同步前后已核实的数据比较。首次同步作为建立基线的导入展示；没有历史依据时不判断为重新激活。新评论只有在取得相关动态后才能确认，详情尚未更新时不宣称已检查全部回复。

事项维护独立的“最近查看版本”。用户打开详情并成功读到内容后，标记该版本已读；仅同步、预取或生成摘要不会将其标记已读。

在此基础上，用户可以生成“需要关注的变化”，例如“你负责的两个 Bug 有新回复，其中一个反馈仍可复现”。每条结论链接到具体变化与原始动态，并保留同步数据截至时间。

### 7.7 个人计划与日历

列表、详情和今日建议均提供“加入今日计划”。用户可以只选日期，也可以设置开始时间、时长和预计投入；只有日期的事项进入当日清单，有明确时间的事项显示在日历时间线。

个人计划不会更改禅道状态、指派人或业务截止日期。拖动日历时间块只更新本机个人排期；已转交和已处理事项保留来源与处理记录。

用户可以从今日计划直接进入详情处理。AI 生成的排期建议需要用户确认，时间冲突在保存前明确显示。

### 7.8 常用工作视图

用户可以保存工作视图、搜索词、类型、优先级、日期条件和排序，例如“高优先级 Bug”“本周待完成任务”“已转交待跟进”。

保存的视图支持命名、修改、删除和设为默认，均保存在本机。进入视图时按当前数据重新计算，不保存某次查询的固定结果。

### 7.9 AI 配置、数据与运行约束

复用设置中现有的服务商、自定义模型名称和密钥配置。用户首次启用禅道智能辅助时，明确查看接收方及发送内容范围，确认后才发出调用；修改为更大的发送范围时再次确认。

首版可发送内容限定为事项编号、标题、描述、状态、指派、日期、选定动态和个人计划字段。登录令牌、密码、附件二进制和本机文件路径不进入提示内容。身份名称可能出现在描述和动态中，需要在发送范围说明中明确列出。

生成状态覆盖未生成、生成中、已生成、已过期和失败。用户可以取消生成；切换事项或再次生成后，迟到结果不能覆盖当前请求。失败信息明确显示原因，页面原有阅读与处理入口保持可用。

摘要按事项及输入内容版本保存，今日建议按日期、候选内容和配置版本保存；两者都设置本机缓存数量及清理边界。服务商或模型切换后，旧结果仍标注原生成配置，新的生成使用当前设置。

禅道描述、动态与 AI 输出均作为内容处理，其中出现的指令不会获得执行权限。生成结果必须通过结构校验，证据引用必须属于本次输入，远端写入继续走明确的操作表单与结果核实流程。

### 7.10 实施前待验证事项

| 待验证事项 | 影响 | 验证方式 |
| --- | --- | --- |
| 当前禅道版本的评论写入接口、权限及回读能力 | 评论功能能否进入第一阶段 | 用独立测试事项验证完整提交与核实过程 |
| 远端截止日期、更新时间和动态标识的完整性 | 排序、已读与证据定位 | 覆盖任务、Bug、重新激活和转交样本 |
| 本机摘要及建议的持久化结构 | 缓存清理与版本失效 | 在实现前确定字段、容量和迁移方案 |
| 所选 AI 模型的结构化输出质量与耗时 | 摘要可靠性和页面等待体验 | 使用至少 30 条样本进行评估，不预设模型效果 |
| 用户是否愿意发送工作内容给所选服务商 | AI 使用范围 | 在首次启用流程中明确告知并取得选择 |

## 8. 分阶段交付与验收

### 第一阶段：能判断，也能连续处理

将“处理排序 + 详情评论 + 处理后下一条 + 智能摘要”作为同一阶段的核心范围。工作流和智能化一起进入实际使用，避免只有建议却无法顺畅执行。

建议按两个增量完成：先交付规则排序、评论与连续处理，再交付有依据的摘要、生成状态和本机缓存。进入开发前先验证评论接口和关键时间字段。

验收重点：排序标签可解释；评论与状态操作经过回读核实；处理后导航不丢失浏览条件；摘要引用可定位，数据变化后明确标记过期；未确认 AI 发送范围时不发出请求。

### 第二阶段：从今日建议进入个人计划

交付今日处理建议、一键加入计划、日期时间与预计投入，以及日历联动。用户可以从推荐事项直接安排当天工作，再回到详情完成处理。

验收重点：推荐数量和输入范围有边界；理由有依据；加入计划需要用户确认；个人排期不修改禅道业务状态；跨天和时间冲突显示清楚。

### 第三阶段：变化驱动的持续跟进

交付同步变化分类、未读标记、智能关注摘要和常用工作视图。完成从发现到后续跟进的闭环。

验收重点：首次导入与后续变化区分明确；新回复结论来自实际动态；读取版本决定已读状态；保存视图按实时数据重新计算；智能关注内容可追溯到具体变化。

### 后续演进

在前述能力稳定并获得使用反馈后，再评估跨事项关联、重复问题提示、相关历史检索和更细的建议偏好。涉及附件理解、代码仓库关联或更大范围的数据发送时，需要单独明确输入权限、成本与验收范围。

各阶段以验收结果作为进入下一阶段的条件，具体排期在接口核查和工作量评估后确定。本文不承诺未经评估的交付日期。

### 第一阶段实施记录（2026-10-27）

- 详情头部改为紧凑两行组织，长标题和窄栏自然换行，标题加大；点击编号复制“【编号】标题：”。
- 建议排序按逾期、今日计划、高优先级分组，支持最近更新；列表显示关注原因、指派人及禅道更新时间。新增远端更新时间字段需要同步后才有数据。
- 提供可记忆的“处理后下一条”选项，只在已核实操作后事项完成或转交时进入后续有效事项。
- 侧栏与完整详情接入按需智能摘要，发送前确认文字预览，复用高级 AI 配置；校验证据引用，正文变化标记过期；本机最多保存二十项、七天有效。
- 当前摘要输入为描述前 12000 字符和最近三十条动态，每条最多 850 字符；“停止等待”会忽略迟到结果，已发出的服务商请求仍可能运行和计费。
- 独立评论采用禅道网页会话：每次输入密码建立本次会话，密码不保存；提交后读取禅道动态，确认新增评论才提示成功。会话接口及账号权限需要在实际实例验证。
- 尚未进行真实 AI 内容评估或真实禅道写入验收，第一阶段暂不能视为整体验收通过。
