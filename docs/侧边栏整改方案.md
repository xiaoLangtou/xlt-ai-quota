# XLT Workbench 侧边栏整改方案

> 适用版本：XLT Workbench v0.1.3
> 涉及文件：`src/layouts/AppLayout.vue`、`src/router.ts`、`src/views/DashboardView.vue`

---

## 一、目标

1. 导航只放**一级入口**，页面内的筛选、维护、配置不占侧边栏。
2. 侧边栏高度固定、不随路由变化。
3. 为 MCP 预留位置，后续加入不用再重构。

---

## 二、现状问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | Skills 组 6 项平铺，配置类、维护类和主功能混在一起 | 层级混乱 |
| 2 | 全局/项目工作区只在 `/skills/*` 出现，且一次列出十几个 Agent | 布局跳变，footer 被挤出可视区 |
| 3 | 工作区大量为 0 或 1 的项，且和根目录管理功能重叠 | 噪音 |
| 4 | 「系统」组只有设置一项 | 浪费一个分组标题 |
| 5 | 问题中心徽章常年为 60（错误和告警混计） | 失去提醒作用 |
| 6 | 命名中英混用，分组标题风格不一，两个"概览"含义不同 | 认知负担 |
| 7 | 副标题「AI 用量 · Skills」未覆盖工具、系统 | 信息不准 |
| 8 | 主题切换在 footer 和设置里各一份 | 重复 |
| 9 | 8 个路由由 `DashboardView` 按 `route.name` 渲染 | 导航语义和页面组件错位 |

## 三、目标结构

```
XLT Workbench
本地工作台

用量
  概览            /dashboard
  分析            /analytics
  订阅与账单       /subscriptions

Skills
  概览            /skills
  技能库  [错误数]  /skills/library
  安装            /skills/install

MCP（预留）
  MCP 服务 [异常数] /mcp

工具
  剪贴板历史       /clipboard
  代码片段         /snippets
  密钥库           /vault
  Git 报告         /daily-report

────── footer（固定）
  设置 · 主题(图标) · 关于
```

侧边栏共 14 项：去掉「系统」组和 3 个 Skills 维护项，新增 1 个 MCP 入口。

---

## 四、具体改动

### 1. 工作区列表移出侧边栏

- 技能库页顶部增加「工作区」下拉（全局 / 各项目 / 各 Agent），沿用现有 `?root=` / `?project=` 参数。
- 下拉内按 Skill 数量降序排序，计数为 0 的项默认折叠到「更多」。
- 侧边栏不再有任何动态列表。

### 2. Skills 维护项收拢到技能库页内

| 原入口 | 新位置 | 路由处理 |
|---|---|---|
| 问题中心 | 技能库的「有问题」筛选 Tab | `/skills/issues` 重定向到 `/skills/library?filter=issues` |
| 回收站 | 技能库右上角「回收站」按钮 | 保留 `/skills/trash`，不进侧边栏 |
| 根目录管理 | 技能库右上角「来源目录」按钮 | 保留 `/skills/roots`，改名「来源目录」 |

### 3. 徽章降噪

- 只统计**错误**（`!valid`），红色。
- 告警不计数，在列表行内用黄色标签展示。
- 数量为 0 时不显示徽章。

### 4. Footer 固定

- 侧边栏拆成三段：头部（品牌）、导航区（独立滚动）、footer（`sticky` 底部）。
- Footer 内容：设置、主题切换（仅图标，点击循环 亮 / 暗 / 自动）、关于。
- 设置页内保留主题选项，作为详细配置入口，footer 只做快捷切换。

### 5. 命名统一

| 原名 | 新名 |
|---|---|
| 用量概览 | 概览（用量组下） |
| 用量分析 | 分析 |
| Skills 概览 | 概览（Skills 组下） |
| 安装 Skills | 安装 |
| 根目录管理 | 来源目录 |
| 分组标题 `SKILLS` | Skills（与其他分组同样式，不强制大写） |
| 副标题 | 本地工作台 |

### 6. MCP 模块（预留）

- 侧边栏先放一项「MCP 服务」，列表 + 启停 + 编辑，「添加」做成页内按钮或抽屉。
- 和 Skills 共用同一个「工作区」筛选组件，支持全局 / 项目范围、按 Agent 过滤。
- 配置异常（解析失败、命令不存在）以行内状态标签展示，不另开问题中心。
- 写入策略：先做只读检测，再做写入；写入前备份，保留未知字段。
- 环境变量和 Token 支持引用密钥库，避免明文落盘。
- 路由：`/mcp`、`/mcp/new`。
- 后续若出现市场/模板等独立功能，再拆出「添加 MCP」菜单项。

### 7. 代码层

- 工具页拆成独立 View：`ClipboardHistoryView`、`SnippetLibraryView`、`VaultView`、`DailyReportView` 已存在，只需让路由直接指向它们。
- 用量三页（dashboard / analytics / subscriptions）和设置页可继续留在 `DashboardView`，或同样拆开，二选一。
- 导航配置抽成一份数据（分组 → 菜单项 → 路由 / 图标 / 徽章来源），`AppLayout.vue` 只负责渲染，后续加 MCP 只改配置。

导航配置示意：

```ts
interface NavItem {
  label: string
  to: string
  icon: string
  badge?: () => number | undefined // 返回 0 / undefined 时不显示
}

interface NavGroup {
  title: string
  items: NavItem[]
}
```

## 五、实施顺序

| 阶段 | 内容 | 风险 |
|---|---|---|
| 第 1 步 | Footer 固定 + 设置移入 footer + 去掉「系统」组 + 命名统一 + 徽章降噪 | 低，纯布局 |
| 第 2 步 | 工作区改为技能库页内下拉，移除侧边栏动态列表 | 中，需改技能库页头 |
| 第 3 步 | 收拢问题中心 / 回收站 / 来源目录，加路由重定向 | 中，注意旧链接兼容 |
| 第 4 步 | 导航配置数据化，拆分 `DashboardView` | 低，重构性质 |
| 第 5 步 | 新增 MCP 服务页 | 独立功能，可并行 |

第 1 步即可解决大部分"乱"的观感，可单独先发布。

---

## 六、验收标准

- [ ] 任意路由下侧边栏高度一致，footer 始终可见。
- [ ] 侧边栏一级入口不超过 14 项，且无动态列表。
- [ ] 徽章为 0 时不显示，不再出现常驻数字。
- [ ] 旧路由（`/skills/issues` 等）访问后自动跳到新位置，不出现 404。
- [ ] 新增导航项只需改配置文件，不改布局代码。

---

## 七、取舍说明

- 收拢维护项会多一次点击，但这三项使用频率低，值得。
- 若不想动路由，最小改法：只做第 1 步，即可解决大部分问题。
- MCP 单独成组而非塞进 Skills：两者同属"Agent 能力扩展"，但配置格式、生命周期不同，分开更利于后续演进。
