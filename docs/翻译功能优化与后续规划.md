# 翻译功能优化与后续规划

更新日期：2026-10-27。本文以当前源码为基线，区分本轮实现与后续规划。编译和逻辑测试不替代真实桌面交互及服务商调用验收。

## 目标

用户可以快速翻译眼前的文本，也可以在工作台连续阅读长文。两个入口共享服务配置，保留各自的使用偏好，并在跳转时延续正在处理的内容和语言方向。

## 当前能力

| 入口 | 当前能力 |
| --- | --- |
| 翻译页 | 原文编辑、语言方向和服务商选择、分段对照、进度、复制译文及双语。 |
| 快捷面板 | 全局快捷键、语言交换、固定窗口、复制、清空、跳转翻译页。 |
| 服务配置 | 有道和 DeepSeek；独立翻译凭据；自定义接口、模型和提示词；快捷键录制与注册状态。 |
| 本机偏好 | 页面和面板分别记忆语言选择；服务商选择写入翻译配置。 |

文本按空行分段，超过 4500 字符的段落继续切分。有道按顺序请求，DeepSeek 最多三路并发，显示顺序始终按原文索引组织。正文采用界面默认字体。

## 本轮优化

### 逐段展示和结果保留

后端每完成一段，就发送该段原文、译文、索引和请求标识。翻译页立即展示完成段落；其他段落仍在处理时继续显示整体进度。部分段落失败时，页面显示错误并保留已经完成的译文，用户可以复制这些结果或重新翻译全文。

这是按段落更新，不是逐字输出。P1 已接入客户端取消和单段重试，详见实施记录。

### 页面和面板衔接

面板跳转时同时传递文本、源语言和目标语言。翻译页在常用方向之外保留面板传入的语言组合，例如日语到简体中文，随后按该方向发起翻译。页面加载配置后再消费交接请求。

### 请求和输入状态

每次请求携带独立标识，翻译页只接收属于当前请求的进度。清空、重新接收面板文本及离开页面后，旧请求的迟到结果不能覆盖当前内容。修改原文或语言方向后清理旧译文，避免把不同输入与旧结果并列显示。

快捷面板仅在原文输入框中响应 Enter 翻译，保留 Shift+Enter 换行；语言选择和按钮使用自己的键盘操作。页面翻译期间锁定原文和方向选择，清空会发出取消请求，停止调度并中断客户端网络等待。已经发送到服务商的请求仍可能被处理或计费。

| 优先级 | 功能 | 用户价值 | 验收范围 |
| --- | --- | --- | --- |

| P1 | 段落状态与复制 | 明确哪些段落完成、失败或仍在等待。 | 保持所有段落的位置；每段显示状态并支持复制；部分结果复制明确标注范围；长文滚动时不跳动。 |
| P1 | 本地翻译历史 | 找回之前翻译的文字。 | 默认关闭，用户启用后保存；按原文、译文和语言搜索；可设保留期限、一键清空；不保存 API Key；失败记录与成功记录区分。 |
| P2 | 截图 OCR 与图片翻译 | 翻译无法复制的界面和文档片段。 | 用户主动截图或选图；先展示识别文字供编辑，再翻译；区分识别错误和翻译错误；明确识别在本机还是远端执行。 |

| P2 | 面板自动翻译开关 | 减少短文本的重复点击。 | 默认手动；开启后输入稳定才请求；中文输入法组合期间不请求；相同输入不重复提交；保留明确的手动入口。 |
| P3 | 文件翻译与导出 | 处理长文档并保留可阅读的结构。 | 先支持 TXT/Markdown，再评估 DOCX/PDF；导入前说明大小和发送范围；预览后翻译；支持译文和双语 Markdown 导出。 |

## 设计约束

- 页面和面板继续复用同一后端及服务配置，不再增加独立的密钥入口。
- 自动翻译、历史保存、截图识别分别由用户启用，不因打开页面而默认发送内容。
- 本地历史需要条数、单条大小和保留期限上限；图片不能无限写入浏览器存储。
- 原文、术语和文档内容作为输入资料处理，不把其中的文字当作应用操作指令执行。
- 服务错误直接呈现具体原因，已完成结果保持可复制。
- P1 的取消、单段重试、段落状态及本地历史已接入源码；OCR、术语表、自动翻译和文件翻译仍待后续实现。

## 验证清单

本轮执行类型检查、生产构建和 Rust 翻译模块测试，并补充交接与 IPC 参数检查。没有启动前端服务，也没有调用真实翻译服务。

桌面验收运行 `pnpm tauri dev`，重点检查：

1. 面板选择日语到中文后跳转，页面保留该方向。
2. 长文段落完成顺序不同时，原文和译文仍正确配对；首段完成后即可阅读。
3. 面板与页面同时翻译，页面进度不受面板请求影响。
4. 部分段落失败时，已完成结果仍可阅读与复制。
5. 清空或离开页面后，旧结果不重新出现。
6. 面板语言选择器按 Enter 只确认选择，不额外发起翻译。

## P1 实施记录

### 请求取消和单段重试

翻译页和快捷面板均提供取消入口。后端按调用窗口和请求标识管理任务，取消会中断客户端正在等待的网络 Future，并停止尚未开始的段落。请求结束或取消后释放注册状态，旧请求的清理不能移除新请求。

每段显示等待、翻译中、完成、失败或取消状态，成功段可以单独复制。失败和取消段可以重试，其他完成段保持原结果。重试绑定上次翻译的配置版本；密钥、模型或提示词等配置变化时拒绝混合重试，提示重新翻译全文。历史恢复仅用于阅读和复制，不携带旧配置版本，因此不直接重试历史段落。

单次输入限制十万字符和二百段。界面显示已开始处理的段数，不将限流重试计为额外段落。取消不能保证服务商停止处理已经收到的请求。

### 本地历史

翻译页的「历史记录」入口提供保存开关、搜索、保留期限和删除操作。默认关闭；开启后，页面和面板后续完成的请求均可以保存。关闭保存不会删除旧记录，删除单条或确认清空后才移除已有内容。

历史保留 7、30 或 90 天，最多 50 条、合计 1MB，单条限制 32KB。超过单条限制时提示未保存，原译文仍可使用；达到总容量时淘汰较早记录。保存字段限于文本、语言、服务、时间和段落状态，不包含调用配置、API Key 或配置版本。

### 本轮验证范围

纯逻辑检查覆盖乱序段落合并、重试保留其他段落、只复制完成段、重复文本交接、取消与重试 IPC 参数，以及历史的期限、条数、字节容量和字段白名单。Rust 检查覆盖窗口与请求取消隔离、旧请求清理、取消后 Future 释放及停止后续调度、配置版本变化，以及原有分段和服务解析测试。

真实桌面仍需验证两个窗口并行请求、取消时网络中断、失败段重试、历史开关与重启后的记录恢复。没有调用真实翻译服务，也没有启动前端服务。
